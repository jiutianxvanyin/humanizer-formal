# 人工审校记录

记录每次人工审校的改前改后与命中规则。不打包进发行版。

用途：规则的增补依据。单次审校的直觉不可信，多次审校的一致倾向可信。
积累到 30 至 50 条之后，判断新条目该不该进就有了依据，而不是靠产出者
自己对「读起来有没有 AI 味」的感觉。

每条记三件事：改前、改后、命中的规则编号。现有规则不覆盖的标「未覆盖」，
这些是新条目的来源。

审校者：玄音。材料：`README.md`，AI 起草，此前已按 v1.0.0 规则做过一轮

### 未覆盖：补全省略的主语、指代与比较项（7 处）

| 改前 | 改后 |
|---|---|
| 降低……AI 生成感 | **本 skill 用于**降低…… |
| 最后一行是核心差异 | **表格**最后一行是**项目的**核心差异 |
| 给**它**已写好的文本，**它**先判定 | 给**使用该 skill 的 AI** 阅读已写好的文本，**让它**先判定 |
| 与英文原版页级或段级严格对齐 | **机翻中文**与英文原版页级或段级严格对齐 |
| 标注了可信度 | 标注了可信度**标签** |
| 最易犯的三条 | 最易犯**错误**的三条 |
| 先定语域 | 先**确定**语域 |

这是改动量最大的一类，v1.0.0 一条未覆盖。机制推测：模型写简介体时照搬
英文的无主语标签式结构，中文读起来悬空。**尚未立条，候选编号 A22。**
可用现有机翻语料检验：数「它 / 其 / 这」密度对照英文原版的 it / this。

### 未覆盖：去缩略口语，动词补足（8 处）

一律要改→一律修改；缺了→缺少会导致；降的是→降低的是；不出现→不会出现；
砍掉→适当删减；说明不了任何事→不说明任何问题；规则从哪来→规则来源；
挂数据→提供证据。

**未立条。** 判断是这不该做成词表，而是「对外文档比内部规则文件高半级」的
语域问题。同一个「砍掉一半」在 `SKILL.md` 的操作指令里合适，在 README 里
不合适。
